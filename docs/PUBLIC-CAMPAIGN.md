# Public adoption.is campaign

`npm run dev:launch` starts the existing owned local Convex harness. Open `/` for the account-free campaign, `/entries/<entryId>` for an approved ad, and `/fundraise/<entryId>` for its tracked fundraising destination. Private manager and creator workspaces use `?workspace=manager` and `?workspace=creator`. The local public configuration endpoint returns only the backend URL; public viewing does not request a fixture session or Clerk identity.

The homepage and detail queries project the current approved entry/version from the persistent adoption campaign. Approval alone makes waiting creative public; there is no paid-slot, funding or trial condition. Pending/rejected entries and entries belonging to another nonprofit produce no public detail. Version history, staff feedback, invitation emails, private identity and storage coordinates remain private.

Creators can choose a public creator name on photo/video submission. That name is part of the version staff reviews. Leaving it blank assigns an opaque, stable campaign creator identifier derived from the persistent campaign and creator identities; unnamed legacy entries receive the same deterministic attribution. Neither an email nor a raw Clerk subject is published. Descriptive edits retain the entry/link and require review. Replacement media after approval creates a separate entry/link, retaining the original creative and history.

The tracked path is deterministically bound to the immutable competition-entry ID at creation, including exact/concurrent retries. Share the same `/fundraise/<entryId>` on every platform. Query parameters cannot replace its origin. `publicViewer:fundraising` exposes the approved origin for later donation integration; it does not create entries or record donations. Checkout is explicitly unavailable until its separate financial integration is implemented and approved. No charge, donation, ad placement or payout is dispatched by this slice.

Public photos are re-encoded viewing derivatives with metadata stripped. Exact originals remain behind private authenticated endpoints. Video viewing issues short-lived signed Mux playback, never original/source-download access. Media capabilities are checked against the current approved entry, reviewed version, upload owner and nonprofit at issuance. Synthetic playback delivery also rechecks the entry/version. Already-issued real Mux grants expire after five minutes; downloaded media cannot be recalled. Missing media shows `This ad's media is unavailable`, offers retry and leaves the tracked action accessible. An empty campaign shows `No approved ads yet` without replacement content.

`npm run build:launch` emits both `index.html` and the retained `launch-preview.html` in `launch-site/`. `vercel.launch.json` is the dedicated launch-project configuration: it selects that output and rewrites entry/fundraising deep links to the public entry. It does not change the existing demo's build or publish anything. A future authorized deployment must select this configuration, configure `VITE_CONVEX_URL`, provide the existing server-side media configuration, and deploy the application Convex functions. Private workspaces additionally require the existing Clerk configuration. Actual hosted deployment, real Clerk and real Blob/Mux capability evidence remain separate T38/T39/release gates.

Anonymous photo requests currently re-encode approved originals on demand (up to the existing 100,000,000-byte per-photo allowance). The local checks establish correctness, privacy and retry behavior, not hosted throughput/cost or provider limits. Production capacity evidence and any derivative cache must retain current approval/version checks; originals must never become public to optimize delivery.

Run `npm run test:launch:backend` for actual isolated persistence, current-permission denials, cross-nonprofit controls, exact/concurrent retry, replacements, media failure and restart checks. Run `npm run test:launch:browser` for desktop/mobile journeys, including a production bundle configured only with the owned Convex URL and no Clerk/session authority. These are bounded local engineering results, not actual provider approval.
