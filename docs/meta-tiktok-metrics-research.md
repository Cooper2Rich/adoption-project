# Meta and TikTok paid-ad reporting research

Research checked 2026-11-07. This note concerns advertiser-owned paid-ad reporting, not organic post insights or public ad libraries. API versions, access rules, and metric availability must be verified for the account and API version used in an implementation.

## Metric comparability

- TikTok defines **impressions** as the number of times ads were shown. Its basic reporting API calls the field `impressions`; a separate `gross_impressions` includes invalid impressions. Its **Clicks (destination)** counts clicks leading to a specified destination, while **Clicks (all)** also includes social interactions. The basic report field `clicks` is labeled Clicks (destination). [TikTok metric definitions](https://ads.tiktok.com/resources/help/article/basic-data?lang=el-GR); [TikTok API metric mapping](https://business-api.tiktok.com/portal/docs/supported-metrics-for-a-dimension-in-basic-reports/v1.3).
- Meta's Audience Network glossary defines impressions as times ads were on screen and counts an ad instance when it first appears on screen. This is an official publisher-side definition, not proof that every Meta placement follows exactly the same measurement rules. [Meta glossary](https://www.facebook.com/audiencenetwork/resources/glossary).
- Meta's own Marketing API example requests `impressions`, `clicks`, `inline_link_clicks`, and `outbound_clicks` as distinct fields. It establishes field availability in the example, but not precise semantic equivalence with TikTok's destination clicks. [Meta Insights example](https://www.postman.com/meta/workspace/facebook-marketing-api/request/31691153-cd811e13-b38e-42d9-9710-a947684b6b0a).
- **Inference:** impressions are directionally comparable as reported paid-ad display counts, and Meta `inline_link_clicks` and TikTok `clicks` are candidate destination-oriented click measures. Do not represent them as identical, landing-page views, unique people, or universal off-platform clicks without confirming the Meta field definition and destination treatment for the selected ad formats. Preserve provider names and raw metric fields. Do not substitute Meta `clicks` or TikTok Clicks (all) for destination-oriented clicks.

## Breakdowns and completeness

- Meta publishes an account-level Insights example with `breakdowns=age,gender` and another with `level=ad`, `time_increment=1`, `breakdowns=product_id`, and `action_breakdowns=action_type,action_destination`. These examples are not a promise that every combination, metric, placement, or account is supported. Meta list endpoints can paginate; consume every page. [Meta account breakdown example](https://www.postman.com/meta/facebook-marketing-api/request/u38qbri/get-insight-details-from-an-adaccount-l4); [Meta daily ad example](https://www.postman.com/meta/facebook-marketing-api/request/5wdl62t/attributionsetting); [Meta API collection](https://www.postman.com/meta/facebook-marketing-api/collection/0zr4mes/facebook-marketing-api-mapi).
- TikTok documents supported metrics separately by dimension and synchronous versus asynchronous mode. For example, `country_code` supports `impressions` and `clicks` in both, but not `reach` in asynchronous basic reports. With `search_terms`, impressions can be the string `<5`, not a precise integer. Async reports do not support UV metrics with targeting dimensions, and lifetime reports do not support time, audience, or country breakdowns. [TikTok dimension compatibility](https://business-api.tiktok.com/portal/docs/supported-metrics-for-a-dimension-in-basic-reports/v1.3); [TikTok async reporting](https://business-api.tiktok.com/portal/docs/create-an-asynchronous-report-task/v2.0).
- TikTok synchronous reports include `page_info` and warn of ID cutoffs; when multiple advertisers are requested, up to 20,000 IDs are returned, ordered by creation time, with no guarantee of even distribution. Inspect warnings and fetch all pages; pagination alone does not remove an ID cutoff. Synchronous date limits depend on granularity: day 30 days, hour 1 day, week 180 days, otherwise 365 days. [TikTok synchronous reporting](https://business-api.tiktok.com/portal/docs/run-a-synchronous-report/v2.0).
- Empty rows, unsupported fields, redacted values, truncation, API errors, permission errors, and incomplete pages must not silently become zero. Store report grain, filters, dimensions, metric availability, pagination/cutoff state, and fetch timestamp; compare a breakdown to the corresponding unbroken total only after validating matching scope and timing. Neither vendor evidence above guarantees that breakdown rows always sum to the total.

## Time and freshness

- TikTok documents normal real-time basic-report latency of about 30 minutes for non-UV metrics without specified special dimensions; it may reach or exceed two hours in extreme cases. Real-time data can be adjusted the following day, and TikTok recommends pulling after its daily 12:00 UTC correction. Some dimensions or metric types are offline with 16-hour latency; `behavior_id` and `purchase_intention` audience reports have 24-hour latency. These are typical latencies, not finality guarantees. [TikTok report latency](https://business-api.tiktok.com/portal/docs/data-latency-for-reports/v1.3).
- TikTok synchronous report dates for ads use the ad-account time zone. For multiple advertisers, it can return local zones or UTC; `query_in_utc0=true` sets returned metrics to UTC+0. Async start/end dates use each ad account's time zone. Daily local dates across different time zones therefore do not automatically describe the same interval. [TikTok synchronous reporting](https://business-api.tiktok.com/portal/docs/run-a-synchronous-report/v2.0); [TikTok async reporting](https://business-api.tiktok.com/portal/docs/create-an-asynchronous-report-task/v2.0).
- Preserve provider account time zone, the requested date range and query settings, and last-refresh time. Mark recent data provisional and re-fetch an overlapping window. The accessible Meta primary sources reviewed did not establish a reliable general freshness/finality SLA or precise daily time-zone conversion behavior; verify against current Meta documentation and a real account before promising either.

## Authorization

- Meta's Marketing API collection requires a developer account, app, access token, permissions and ad account. It supports user or system-user tokens. It says Standard Access with `ads_read` and `ads_management` suffices for managing one's own ad account, and Advanced Access to `ads_read` and/or `ads_management` is needed for managing others' accounts. Request only the permissions actually required, and verify read-only access for the chosen endpoints; access to a particular account must also be granted. [Meta Marketing API collection](https://www.postman.com/meta/facebook-marketing-api/collection/0zr4mes/facebook-marketing-api-mapi).
- TikTok requires developer registration, an app, advertiser authorization, and an advertiser access token. Its v2.0 reference lists `Reporting > Consolidated Report` for both synchronous and async report endpoints. The authorizing user must also have access to the relevant ad account; otherwise TikTok documents insufficient advertiser permission errors. Its authorization FAQ says the Marketing API advertiser token does not expire but can be revoked; authorization can also be revoked by the advertiser. [TikTok authorization](https://business-api.tiktok.com/gateway/docs/index?doc_id=1738373141733378&identify_key=c0138ffadd90a955c1f0670a56fe348d1d40680b3c89461e09f78ed26785164b&language=ENGLISH); [TikTok API reference](https://business-api.tiktok.com/portal/docs/api-reference/v2.0); [TikTok authorization FAQ](https://business-api.tiktok.com/gateway/docs/index?doc_id=1766037914914818&identify_key=c0138ffadd90a955c1f0670a56fe348d1d40680b3c89461e09f78ed26785164b).
- Public ad libraries do not replace authorized account reporting: Meta describes the library as an ad-discovery service with additional detail for particular regulated categories, rather than a general advertiser performance feed. [Meta Ad Library](https://business.facebook.com/ads/library).
